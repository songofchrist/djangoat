Overview

The following constants will be referenced in certain examples below:
  • DATE_FORMAT: "F jS, Y"
  • TIME_FORMAT: "F jS, Y g:i a"
  • NUM_DICT: {'one': 1, 'two': 2, 'three': 3}
The following context variables will be referenced in certain examples below:
  • posts: a queryset of all posts
The following DATA functions (registered to djangoat.DATA) will be referenced in certain examples below:
  • DATA['now']: returns the current time
  • DATA['cube_func']: cubes ARG1
  • DATA['power_func']: takes ARG1 to the power of ARG2
  • DATA['range_func']: creates a range with a length of ARG1

Tags

dict

{% verbatim %}{% dict DICT_NAME [clear] set KEY_1 %} . . . {% set KEY_2 %} . . . {% enddict %}{% endverbatim %}

This tag sets the given keys of the dict DICT_NAME to the rendered content of each subsequent block. If no such dict exists, it will be created. If the clear keyword is provided, the dict will be cleared prior to setting values. The primary intent here is to be able to create to allow for the inline creation of an object that might then be passed to an existing template that expects to receive that object, as opposed to that object needing to be created within a view and passed in via context.

{% verbatim %}{% dict 'test_dict' set 'one' %}<b>One</b>{% set 'two' %}<i>Two</i>{% enddict %}

test_dict = {{ test_dict }}

One: {{ test_dict.one }}

Two: {{ test_dict.two }}{% endverbatim %}
 {% dict 'test_dict' set 'one' %}One{% set 'two' %}Two{% enddict %} test_dict = {{ test_dict }}
One: {{ test_dict.one }}
Two: {{ test_dict.two }} 
{% verbatim %}{% dict 'test_dict' set 'one' %}One{% set 'two' %}Two{% enddict %}

{% dict 'test_dict' clear set 'three' %}Three{% set 'four' %}Four{% enddict %}

test_dict = {{ test_dict }}{% endverbatim %}
 {% dict 'test_dict' set 'one' %}One{% set 'two' %}Two{% enddict %} {% dict 'test_dict' clear set 'three' %}Three{% set 'four' %}Four{% enddict %} test_dict = {{ test_dict }}

list

{% verbatim %}{% list LIST_NAME [clear] append %} . . . {% append %} . . . {% endlist %}
--- OR ---
{% list LIST_NAME set INDEX %} . . . {% set INDEX %} . . . {% endlist %}{% endverbatim %}

This tag operates on an existing list LIST_NAME from context (or creates the list if no such list exists). It supports two operations: "append" and "set". The "append" operation will append the rendered block that immediately follows to the list. The "set" operation will set the item at the given index to the value of the subsequent block. Operations may not be mixed.

{% verbatim %}{% list 'test_list' append %}<b>One</b>{% append %}<i>Two</i>{% endlist %}

test_list = {{ test_list }}

{% list 'test_list' set 0 %}<b>SUBSTITUTE</b>{% endlist %}

altered_test_list = {{ test_list }}

{% list 'test_list' clear append %}<b>Three</b>{% append %}<i>Four</i>{% endlist %}

replaced_test_list = {{ test_list }}{% endverbatim %}
 {% list 'test_list' append %}One{% append %}Two{% endlist %} test_list = {{ test_list }}
{% list 'test_list' set 0 %}SUBSTITUTE{% endlist %} altered_test_list = {{ test_list }}
{% list 'test_list' clear append %}Three{% append %}Four{% endlist %} replaced_test_list = {{ test_list }}

 {% method posts.0 'get_byline' 1 1 %}

pager

{% verbatim %}{% pager QUERYSET ITEMS_PER_PAGE PLUS_OR_MINUS %}{% endverbatim %}

Using the settings in the "djangoat.PAGER" dict, this tag generates a page navigation widget for the provided queryset. "Items per page" and "plus or minus" may be adjusted on a per-page basis by supplying these as arguments. By following the pager links, a "page" parameter (by default) will be added to the url, and items display will adjust accordingly. Note that the pager widget will need to be styled as is appropriate to your site.

{% verbatim %}{% pager posts 2 %}  # prep the "pager_queryset" and widget
<h1>Posts</h1>
<hr>
{% for post in pager_queryset %}
  POST DISPLAY
{% endfor %}
<hr>
{{ pager }}  # the pager widget{% endverbatim %}
 {% pager posts 2 %}

Posts

{% for post in pager_queryset %}

{{ post.title }}

{% endfor %}
{{ pager }}
